# Presto/Trino .NET 客户端性能对比报告

> 对应库版本：v1.0（未发版） | 测试日期：2026-11-22
> 配套工程：`PerfTest/`（一键复现，见文末） | 竞品矩阵见 [竞品分析](./竞品分析.md)

**结论：两个引擎上，本项目在 ADO 组内全部查询场景耗时最低或持平；8 并发吞吐略低于原始 HTTP 协议基线，与最快竞品互有胜负。托管分配全部场景最低，为竞品的 9%–52%，也低于原始 HTTP 基线。**

## 1. 范围与客户端

| 客户端 | 类型 | 说明 |
|--------|------|------|
| NewLife.Presto | ADO（自研，零第三方依赖） | 本报告被测对象 |
| Trino.Ado 1.1.0 | ADO | 官方系，基于 Trino.Core |
| Trino.Client.ADO 1.0.11 | ADO | 官方系旧版封装 |
| NReco.PrestoAdo 1.1.0 | ADO | 薄层 + PrestoClient，主表用 `CheckInterval=50`（默认 1000 ms 每次查询 2–4 秒） |
| 原始 HTTP v1 | 协议基线 | `HttpClient` 直接调 `/v1/statement`，不含客户端抽象 |

环境：Windows 10 / i9-10900K / 64 GB，客户端 .NET 10 Release；服务端在 WSL2 Ubuntu 24.04 单节点，Trino 476（:8080）与 PrestoDB 0.300（:8081），本地回环、明文、无认证。

## 2. 场景与方法

| 场景 | 内容 |
|------|------|
| 建连 + 首查 | `new 连接 + Open + ExecuteScalar`，含握手 |
| 标量查询 | 复用连接执行 `SELECT 1` |
| 聚合 15000 行 | `count(*)`，服务端聚合、结果一行 |
| 扫描 15000 行 | `sequence(1,5000) × sequence(1,3)`，逐页拉完并逐行取值 |
| 多列类型 5000 行 | bigint / varchar / decimal / date 四列 |
| 宽表 16 列 5000 行 | 10 整数 + 6 字符串，单页 8 万单元格 |
| 8 并发 | 8 条独立连接 × 5 次，统计吞吐 |

方法：同一进程串行执行，所有客户端读到的行数/校验和一致；每场景先预热 3 次并强制 GC 再采样；整轮重复 3 轮取中位；分配取 `GC.GetTotalAllocatedBytes(precise: true)`。服务端单页行数在 255–5000 之间浮动，轮间波动可达 20%–80%，因此结论看排序与数量级，不看小数点。

## 3. 结果

**Trino 476**（毫秒，越小越好）

| 场景 | 本项目 | 最快 ADO 竞品 | 原始 HTTP | 分配（本项目 / 竞品） |
|------|------:|-------------:|---------:|---------------------|
| 建连 + 首查 | **8.05** | 11.70 | 9.03 | **24 KB** / 98 KB |
| 标量 `SELECT 1` | **7.53** | 9.21 | 7.44 | **15.7 KB** / 95 KB |
| 聚合 15000 行 | **15.50** | 15.98 | 17.45 | **16.6 KB** / 96 KB |
| 扫描 15000 行 | **20.76** | 76.46 | 20.27 | **0.54 MB** / 2.39 MB |
| 多列类型 5000 行 | **21.09** | 22.22 | 22.93 | **0.94 MB** / 4.11 MB |
| 宽表 16 列 5000 行 | **29.65** | 41.86 | 57.82 | **3.34 MB** / 6.37 MB |
| 8 并发（次/秒） | 178.1 | **190.3** | 179.6 | **0.74 MB** / 3.75 MB |

**PrestoDB 0.300**（毫秒，越小越好）

| 场景 | 本项目 | 最快 ADO 竞品 | 原始 HTTP | 分配（本项目 / 竞品） |
|------|------:|-------------:|---------:|---------------------|
| 建连 + 首查 | **13.66** | 16.94 | 16.09 | **19 KB** / 168 KB |
| 标量 `SELECT 1` | **13.21** | 17.68 | 12.99 | **11.1 KB** / 101 KB |
| 聚合 15000 行 | **18.87** | 27.08 | 18.05 | **12.3 KB** / 142 KB |
| 扫描 15000 行 | **32.62** | 52.58 | 35.81 | **0.54 MB** / 2.52 MB |
| 多列类型 5000 行 | **38.20** | 40.24 | 49.52 | **0.94 MB** / 4.13 MB |
| 宽表 16 列 5000 行 | **66.78** | 67.01 | 98.15 | **3.38 MB** / 6.50 MB |
| 8 并发（次/秒） | 135.5 | 127.3 | **146.5** | **0.65 MB** / 3.96 MB |

要点：

1. **ADO 组内全部延迟场景耗时最低或持平**：标量耗时只有竞品的 75%–82%，扫描 27%–62%，建连 69%–81%；PrestoDB 宽表两者相差 0.3%，属持平量级。
2. **托管分配全部最低**：为竞品的 9%–52%，且**低于原始 HTTP 基线**（基线只做协议读写、不建对象）。
3. **与协议基线的差距**：标量 1%–2%、扫描 2%（Trino）与 5%–9%（PrestoDB）、聚合 4%（PrestoDB 上基线更快），均在轮间波动内；并发吞吐两项都略低于基线（低 1%–8%）。
4. **轮询间隔对 NReco 影响很大**：默认 `CheckInterval=1000 ms` 会让单次查询增加 2–4 秒；本轮已调到 50 ms，仍是本组最慢（185–290 ms/次）。

## 4. 主要优化方向

| 方向 | 做法 | 效果 |
|------|------|------|
| 流式解析 | `net6+` 用 `Utf8JsonReader` 直接吃 UTF-8 响应字节，池化缓冲，数字/日期/时间戳在字节上直转 | 标量 156 → **15.7 KB**；时间戳 15000 行 2.51 → **1.48 MB** |
| 扁平行存储 | 单页数据存进连续数组、`Data` 延迟展开，上限 26 万单元格 | 扫描 5.3 MB → **0.54 MB**；宽表 44.5 → **29.7 ms** |
| 通道与复用 | 同步 API 走真同步通道；认证头/请求头/URI/重试策略/跨页字符串复用；中间页只留进度统计 | 建连 104 → **24 KB**，标量再降 40% |
| 协议取舍 | 默认不请求压缩（广域网可开 `Compression=true`）、终态查询免取消、复杂列直接切原始 JSON 文本 | 扫描快 20%，认证头额外分配 3.90 → **0.72 KB** |
| 取值 | 与列类型一致时直接返回、数值就近转换、复杂列 JSON 文本、`timestamp` 直转 | 多列 1.43 MB → **0.94 MB** |

## 5. 边角验证

- **百万行扫描**（TPC-H sf1 lineitem 1,000,049 行）：本项目 557 ms / 71 MB / 峰值 55 MB，Trino.Ado 2466 ms / 164 MB，Trino.Client.ADO 2342 ms / 159 MB，三方校验和一致。
- **GC 压力**（1000 标量 + 20×15000 行扫描）：本项目 25.4 MB、0 次 Gen2；两个官方系客户端 140–150 MB、各 2 次。
- **异步 API**：比同步多约 7 KB/查询（裸 HTTP 异步同样 +7–8.5 KB，属 `HttpClient` 固有）。
- **TLS**（Kestrel 反向代理）：首连 +3.3 KB 分配，请求级开销在噪声内，握手被共享连接池摊薄。
- **复杂列**（array/map/row）：默认返回协议原始 JSON 文本；5000 行 × 2000 元素数组 584 ms / 95 MB。

## 6. 局限

- 单机回环、明文、无认证服务端；TLS 与认证只做了客户端侧量化。
- 页大小不固定、轮间波动大，单轮数值只能作参考，排序结论以多轮 A/B 为准。
- 流式解析只覆盖 `net6+`；`net45`/`net461`/`netstandard2.x` 走字典路径，分配高于本表。
- 竞品对 `decimal`/`date` 返回非标准类型，基准已按字符串归一化后比较，成本计入其耗时。
- 未覆盖：AOT 发布后的性能、单列 >64 KB 超长字符串、真实 JWT/OAuth2 服务端。

dotnet run tools/DbCtl.cs -- start trino      # 8080
dotnet run tools/DbCtl.cs -- start presto     # 8081

dotnet run --project PerfTest -c Release -- --engine presto --port 8081 --repeat 3 --exclude "（默认）"
