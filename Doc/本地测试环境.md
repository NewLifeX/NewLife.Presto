# 本地测试环境（Trino / PrestoDB）

> 结论：Trino 与 PrestoDB 的发行包都硬性检查操作系统（启动即报 `requires Linux or Mac OS X`），**Windows 原生跑不起来**。
> 本机通过 WSL 运行，发行版虚拟磁盘位于 `E:\WSL\Ubuntu-24.04`，数据库安装在发行版内的 `/opt/dbservers`，不占 C 盘。
> 用 [tools/DbCtl.cs](../tools/DbCtl.cs) 一条命令完成安装与启停，配合 `PRESTO_TEST_CONNSTR` / `TRINO_TEST_CONNSTR` 跑真库集成测试。

## 1. 版本与 Java 要求

| 服务 | 版本 | 端口 | Java | 依据 |
|------|------|------|------|------|
| Trino | 476 | 8080 | 24+（Zulu 25） | `trino-main` 字节码 major 68 |
| PrestoDB | 0.300 | 8081 | 17（apt openjdk-17） | `presto-main` 字节码 major 61 |

两个引擎都不能以 Windows 进程运行；安装文件本身可以放在任意磁盘，本机放在 E 盘的 WSL 发行版里。

## 2. 一键安装与启停（推荐）

```powershell
# 查看状态：发行版、安装目录、进程、端口
dotnet run tools/DbCtl.cs -- status

# 启动（未安装时自动下载 JDK 与发行包；已安装则直接启动）
dotnet run tools/DbCtl.cs -- start trino            # 默认 8080
dotnet run tools/DbCtl.cs -- start presto           # 默认 8081
dotnet run tools/DbCtl.cs -- start trino --port 18080

# 停止（只结束本工具启动的实例；其它会话的实例需加 --force）
dotnet run tools/DbCtl.cs -- stop trino
dotnet run tools/DbCtl.cs -- stop presto --force

# 只安装不启动；清理下载缓存（--purge 连安装一起删）
dotnet run tools/DbCtl.cs -- install presto
dotnet run tools/DbCtl.cs -- clean [--purge]
```

脚本行为：

- 发行版不存在时，自动下载 Ubuntu base rootfs 并 `wsl --import` 到**空余空间最多的固定磁盘**（当前为 `E:\WSL\Ubuntu-24.04`）。
- 组件缺失时自动下载：Trino/Presto 发行包来自 Maven 聚合镜像（`maven.aliyun.com`），JDK 来自 Azul CDN；解压到 `/opt/dbservers/{trino-476|presto-0.300|jdk25|jdk17}`。
- Presto 的 Java 17 优先复用发行版自带的 `/usr/lib/jvm/java-17-openjdk-amd64`（通过 `/opt/dbservers/jdk17` 软链），缺失时才下载 Zulu 17。
- 启动时保持一个 WSL 保活会话，避免 WSL 空闲停机把数据库带走；所有数据库都停止后自动释放。
- 端口已有实例时直接复用；被其它进程占用但未就绪时等待，不会重复起第二个实例。

启动成功会打印连接串：

```text
Host=localhost;Port=8080;Catalog=tpch;Schema=tiny;User=test;Protocol=Trino
Host=localhost;Port=8081;Catalog=tpch;Schema=tiny;User=test
```

## 3. 手工安装参考（脚本内部等价步骤）

下载源（本机网络无法直连 Docker Hub / GitHub）：

```bash
# JDK 25（Trino）
curl -o zulu-jdk25.tar.gz https://cdn.azul.com/zulu/bin/zulu25.38.201-ca-jdk25.0.5.1-linux_x64.tar.gz
# JDK 17（Presto，或 apt install openjdk-17-jre-headless）
curl -o zulu-jdk17.tar.gz https://cdn.azul.com/zulu/bin/zulu17.70.201-ca-jdk17.0.21.1-linux_x64.tar.gz
# 发行包（Maven Central 镜像）
curl -o trino-server-476.tar.gz https://maven.aliyun.com/repository/public/io/trino/trino-server/476/trino-server-476.tar.gz
curl -o presto-server-0.300.tar.gz https://maven.aliyun.com/repository/public/com/facebook/presto/presto-server/0.300/presto-server-0.300.tar.gz
```

解压到 `/opt/dbservers/<名称>` 时使用 `--strip-components=1`，安装包顶层目录会被去掉。启动命令（脚本内部使用）：

```text
# Trino
<jdk25>/bin/java -server -Xmx3G -Dnode.environment=test -Dnode.id=trino-dbctl-01
  -Dnode.data-dir=/opt/dbservers/data/trino -Dconfig=/opt/dbservers/trino-476/etc/config.properties
  -cp "/opt/dbservers/trino-476/lib/*" io.trino.server.TrinoServer

# Presto
<jdk17>/bin/java -server -Xmx2G -Dnode.environment=test -Dnode.id=presto-dbctl-01
  -Dnode.data-dir=/opt/dbservers/data/presto -Dconfig=/opt/dbservers/presto-0.300/etc/config.properties
  --add-opens=java.base/java.nio=ALL-UNNAMED --add-opens=java.base/java.lang=ALL-UNNAMED
  -cp "/opt/dbservers/presto-0.300/lib/*" com.facebook.presto.server.PrestoServer
```

## 4. 验证

```bash
curl -s http://127.0.0.1:8080/v1/info    # Trino，starting=false 即就绪
curl -s http://127.0.0.1:8081/v1/info    # Presto
```

WSL2 默认开启 localhost 转发，Windows 侧可直接访问 `http://localhost:8080` 与 `http://localhost:8081`。

## 5. 运行全部测试

```powershell
$env:TRINO_TEST_CONNSTR  = 'Host=localhost;Port=8080;Catalog=tpch;Schema=tiny;User=test;Protocol=Trino'
$env:PRESTO_TEST_CONNSTR = 'Host=localhost;Port=8081;Catalog=tpch;Schema=tiny;User=test'

pwsh -File tools/test-all.ps1        # 构建、单元+真库集成、覆盖率、控制台冒烟、AOT、门禁、打包消费端
```

未设置连接串时集成测试自动跳过。真库用例覆盖提交与轮询、类型取值、`@` 参数替换、15000 行多页结果、GetSchema 四个集合与错误映射；AotSmoke 的 `--connstr` 会在 NativeAOT 下走一遍 HTTP 查询链路。

Spooling 用例分两层：离线测试用假 HTTP 处理器覆盖内嵌/对象存储分段与确认请求；真库只验证 Trino 未配置对象存储时的直接协议回退。完整 Spooling 下载需要 Trino 配置 S3/Azure/GCS，本机暂未提供。

## 7. 常见问题
- **Windows 原生启动报 `requires Linux or Mac OS X`**：这是引擎的硬性检查，不是配置问题；只能通过 WSL（或 Linux 容器/主机）运行。
- **端口上的实例不是本工具启动的**：`stop` 只会结束本工具的进程并提示 `NOT_OURS`；确认可以结束后加 `--force`（会按主类强制结束）。
- **WSL 空闲停机**：工具在启动数据库时会保持一个保活会话；手动执行 `wsl --shutdown` 会一并停止数据库。
- **WSL 内 `dotnet` 报 Bus error (SIGBUS)**：宿主机磁盘写满后 ext4 写入失败导致文件损坏；`dpkg -V` 定位，重装 `dotnet-host` 等包可修复。
- **磁盘空间**：安装目录在 WSL 发行版内（`E:\WSL\Ubuntu-24.04`）；如需迁移发行版，用 `wsl --manage Ubuntu-24.04 --move <目标目录>`。

## 8. 竞品性能对比（可选）

`PerfTest/` 是独立的基准工程（不参与解决方案构建），在同一进程内对比本项目驱动与三个主流 ADO 客户端，外加原始 HTTP 协议基线：

```powershell
dotnet run tools/DbCtl.cs -- start trino
dotnet run --project PerfTest -c Release -- --engine trino --port 8080 --repeat 3 --out .tmp/性能测试-trino.md
dotnet run --project PerfTest -c Release -- --engine presto --port 8081 --repeat 3 --out .tmp/性能测试-presto.md
dotnet run --project PerfTest -c Release -- --probe        # 只探测连通性
dotnet run --project PerfTest -c Release -- --only NewLife # 只跑指定客户端
```

方法与结果见 [性能测试](性能测试.md)；工程内包含 Trino.Ado、Trino.Client.ADO、NReco.PrestoAdo 三个竞品包引用，仅用于对比，不会进入发布产物。
