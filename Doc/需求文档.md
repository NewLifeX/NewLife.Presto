# NewLife.Presto 需求文档

> 版本：v1.0 | 日期：2026-11-20
> 本文档描述 NewLife.Presto 的愿景、核心目标和功能方向。完成状态在[功能清单](功能清单.md)中追踪，详细设计在[架构设计](架构设计.md)中展开。

## 一页纸摘要

- **一句话**：纯 C#、零第三方依赖的 Presto/Trino ADO.NET 驱动，面向 XCode ORM 与 ADO.NET 应用，最终成为 XCode 中 Presto 的默认驱动。
- **核心模块**：SYS 系统基础、PROTO 协议、SQL 查询执行、META 元数据、COMPAT 兼容性、I18N 多语言、XCODE 集成、QA 质量与交付。
- **工程要求**：33 种运行时语言、11 种 README 语言、`net45`~`net11` 多目标框架、NativeAOT、Windows/Linux/macOS 与多指令集覆盖。
- **非目标**：不做数据库服务端、不做事务/DDL/自增/批量导入、不做 Presto 集群管理 API、不做 EF Provider 的核心内置实现。
- **当前状态**：核心驱动已实现并通过 484 项单元测试与真库集成；本轮补齐 DbBatch、OAuth2 客户端凭据、查询诊断 API 与复杂类型结构化，并治理短查询延迟与托管分配。
- **待拍板**：无阻塞项。EF Provider、OAuth2 交互式登录、Spooling 协议等保留在暂缓清单。

## 1. 背景与愿景

### 1.1 系统定位

**纯国产、零第三方依赖、面向 XCode 的 Presto/Trino ADO.NET 驱动**。基于 Presto/Trino 官方 HTTP REST v1 客户端协议，覆盖只读分析查询与连接器允许的显式写入，目标框架覆盖 `net45` ~ `net11`。

| 工程 | 定位 | 目标用户 |
|------|------|---------|
| `NewLife.Presto` | 核心 ADO.NET 驱动 | XCode 开发者、ADO.NET 开发者、BI/报表/数据集成开发者 |
| `UnitTest` | 离线单元测试与假 HTTP 协议测试 | 驱动维护者 |
| `Test` | 最小控制台冒烟工程 | 首次接触项目的开发者 |
| 后续扩展 | EF Core / EF6 Provider、Benchmark、AOT 冒烟 | 按需立项，不进入首版核心包 |

Presto 与 Trino 同源，SQL 方言与客户端协议高度一致；驱动以同一套实现支持两者，通过协议头前缀切换。

### 1.2 愿景

- **XCode 默认**：安装 `NewLife.Presto` 即可被 XCode 识别为 Presto 首选驱动，连接字符串、参数化、元数据与能力边界开箱即用。
- **零第三方依赖**：仅依赖 `NewLife.Core`，不引入 JSON、HTTP、日志等第三方包，降低版本冲突与供应链风险。
- **协议稳健**：正确处理提交、轮询、分页、取消、超时、瞬态错误与服务端新增状态，不因一个未知字段或状态导致整次查询失败。
- **类型保真**：标量类型精确映射到 .NET；日期时间、十进制、二进制、UUID、IP 地址等按类型签名解析，复杂类型有明确的降级策略。
- **可观测、可诊断**：查询 ID、服务端错误码、SQLState、耗时与重试过程可追踪；日志默认不泄露密码、令牌与敏感查询内容。
- **全框架覆盖**：`net45` ~ `net11`，与 XCode 的目标框架保持一致；`net8.0+` 满足 NativeAOT/裁剪分析要求。
- **多语言开箱可用**：异常、日志与驱动元数据内置 33 种运行时语言，英文为源文与兜底；README 覆盖 11 种语言。
- **全平台可交付**：Windows / Linux（glibc 与 musl）/ macOS，x64 / arm64；LoongArch64 与 riscv64 由观察期构建覆盖。

### 1.3 核心竞品（用户提供，详见竞品分析报告）

| 竞品 | 定位 | 值得关注的做法 |
|------|------|--------------|
| 参考实现 A | .NET 生态中的 Presto/Trino ADO.NET 适配器 | 以薄适配层复用 REST 客户端；连接字符串切换 Presto/Trino 协议头；已有生产使用案例 |
| 参考实现 B | .NET 生态中的 Presto REST 客户端 | REST API 覆盖查询之外的管理接口；HTTP 重试、取消与服务端响应建模较完整 |

## 3. 功能需求

### 3.1 SYS — 系统基础

- **SYS-1 连接字符串解析与别名**：解析 Host/Server/Data Source、Port、Catalog/Database、Schema/Owner、User、Password、UseSsl、TrustServerCertificate、Auth、AccessToken、Protocol、TimeZone、SessionProperties、CustomHeaders、Proxy、Path、CommandTimeout、TestConnection、Compression 等参数及常用别名。
- **SYS-2 连接生命周期**：`Open`/`OpenAsync`/`Close`/`Dispose`/`ChangeDatabase` 状态机；默认不在 `Open` 时发起网络探测，`TestConnection=true` 时才请求服务端信息。
- **SYS-3 HTTP 传输与连接复用**：按“端点 + TLS + 认证 + 代理”缓存共享 `HttpClient`；复用底层连接，处理重定向、代理与请求头默认值。
- **SYS-4 TLS 与证书校验**：`UseSsl`/`EnableSSL` 启用 HTTPS；默认严格校验证书；`TrustServerCertificate`/`IgnoreSslErrors` 仅在显式开启时放宽，并记录警告。
- **SYS-5 基础认证**：`User` + `Password` 的 HTTP Basic 认证；密码为空时按无密码模式处理；用户名缺省时按环境用户名、再退化为 `anonymous`，避免因缺少用户头直接失败。
- **SYS-6 JWT/Bearer 认证**：`Auth=JWT` + `AccessToken` 发送 `Authorization: Bearer`；令牌不写入日志；支持调用方在每次请求前刷新令牌的扩展点。
- **SYS-7 自定义请求头**：通过连接字符串或构建器追加自定义头，适配网关、租户标识、链路追踪等场景；禁止覆盖驱动核心头。
- **SYS-8 会话上下文**：设置 `Catalog`、`Schema`、`User`、`Source`、`TimeZone`、`Language`、`ClientTags`、`ClientInfo`、`ResourceGroup`、`TraceToken` 与 `SessionProperties`，并处理服务端返回的 Set-Catalog/Set-Schema/Set-Session 指令。
- **SYS-9 日志与敏感信息脱敏**：使用 `NewLife.Core` 日志接口；默认不输出密码、令牌、完整连接字符串与查询文本；调试日志需显式开启。
- **SYS-10 OpenTelemetry 链路追踪**：`ActivitySource` 名称 `NewLife.Presto`，输出 Open / Execute / Fetch / Cancel 跨度，遵循 OpenTelemetry 数据库语义约定；无订阅者时零额外开销。
- **SYS-11 NativeAOT 兼容**：`net8.0+` 启用裁剪/AOT 分析器零告警；协议与类型编解码不使用运行时反射。
- **SYS-12 OAuth2 客户端凭据**：`Auth=OAuth2` 时用 `TokenEndpoint` + `ClientId` + `ClientSecret`（可选 `Scope`）按 `client_credentials` 获取 Bearer 令牌；按 `expires_in` 提前刷新，令牌不写入日志；`AccessTokenProvider` 回调优先于内置令牌缓存。不做浏览器/设备码等交互式登录。

### 3.2 PROTO — 协议与查询

- **PROTO-1 语句提交**：向 `/v1/statement` POST SQL 文本，携带会话头；解析首个 `QueryResults`。
- **PROTO-2 nextUri 轮询与状态机**：按 `nextUri` 持续 GET，直到 `nextUri` 缺失；状态字段按字符串保存，兼容 `QUEUED`、`RUNNING`、`FINISHED`、`FAILED`、`CANCELED`、`WAITING_FOR_PREREQUISITES` 及未来新增状态。
- **PROTO-3 瞬态错误重试**：对 429、502、503、504 按 `Retry-After` 或指数退避重试；只对安全的 GET/轮询请求自动重试，提交请求默认不重试，避免重复执行。
- **PROTO-4 结果页解析**：解析 `columns`、`data`、`stats`、`warnings`；数据行按页消费，不在内存中累积完整结果集。
- **PROTO-5 错误对象解析与异常映射**：解析 `error.message`、`errorCode`、`errorName`、`errorType`、`sqlState`、`failureInfo`、`errorLocation`；映射为 `PrestoException`，保留查询 ID 与服务端错误码。
- **PROTO-6 取消与超时**：`DbCommand.Cancel()` 与 `CancellationToken` 触发取消，best-effort DELETE `nextUri` 释放服务端查询；支持命令超时；取消异常不被后续清理异常覆盖。
- **PROTO-7 响应压缩**：默认发送 `Accept-Encoding: gzip, deflate` 并自动解压；可通过连接字符串关闭，适配不压缩的网关。
- **PROTO-8 查询统计与警告**：暴露查询 ID、耗时、处理行数/字节数、警告列表，供日志、诊断与上层 UI 使用。
- **PROTO-9 服务端会话指令**：处理响应头中的 Set-Catalog、Set-Schema、Set-Session、Clear-Session、Set-Role 等指令，保持后续请求的会话一致性；不支持的指令记录警告而不中断查询。

### 3.3 SQL — 查询执行

- **SQL-1 DbCommand 执行入口**：实现 `ExecuteReader`/`ExecuteScalar`/`ExecuteNonQuery` 及全链路异步版本；`CommandType` 仅支持 `Text`，其他类型抛出明确异常。
- **SQL-2 `@name` 参数替换**：在字符串字面量、双引号标识符、行注释、块注释之外替换 `@参数名`；支持重复参数与缺失参数检测；XCode 可直接使用 `@` 前缀。
- **SQL-3 参数值格式化**：按参数类型生成 Presto 字面量：NULL、布尔、整数、浮点、十进制、字符串、日期时间、二进制、Guid、数组/集合；字符串单引号转义，二进制使用 `X'...'`。
- **SQL-4 标量类型映射**：boolean/tinyint/smallint/integer/bigint/real/double/decimal/varchar/char/varbinary/json/uuid/ipaddress 等映射到 .NET 标量类型。
- **SQL-5 日期时间类型映射**：date/time/time with time zone/timestamp/timestamp with time zone/interval 映射到 `DateTime`、`DateTimeOffset`、`TimeSpan` 或字符串，保持精度与时区语义。
- **SQL-6 复杂类型降级**：array/map/row/json 默认返回原始字符串；`GetFieldType` 返回 `String`；结构化对象解析列为暂缓。
- **SQL-7 DataReader 基础行为**：`Read`/`ReadAsync`、`GetValue`/`GetValues`、`IsDBNull`、`GetFieldType`、`GetDataTypeName`、`GetOrdinal`、`HasRows`、`RecordsAffected`、`Close`/`Dispose`。
- **SQL-8 GetSchemaTable**：按 ADO.NET SchemaTable 列构建结果集元数据；列名、序号、数据类型、数据类型名、允许 NULL、基数等可用。
- **SQL-9 CommandBehavior**：支持 `Default`、`SchemaOnly`、`SingleRow`、`CloseConnection`；`SchemaOnly` 只取元数据并尽早取消，`SingleRow` 读取首行后停止。
- **SQL-10 ExecuteNonQuery 语义**：优先使用服务端 `updateCount`，其次 DML 结果集的 `rows` 列；无法确定时返回 `-1`，不伪造受影响行数。
- **SQL-11 异步执行与取消传播**：所有 I/O 使用 `async/await`，库内部 `ConfigureAwait(false)`；`CancellationToken` 贯穿提交、轮询、读取与清理。
- **SQL-12 DataAdapter/DataTable 填充**：提供 `PrestoDataAdapter` 或以标准 `DbDataAdapter` 完成只读 Fill；Update/Delete/Insert 明确不支持。
- **SQL-13 DbDataSource（.NET 8+）**：提供 `PrestoDataSource` 与 `PrestoClientFactory.CreateDataSource`，支持 `DbDataSource.CreateCommand`/`OpenConnection` 与连接串热切换。
- **SQL-14 DbBatch（.NET 6+）**：提供 `PrestoBatch`，命令按顺序逐条提交；`ExecuteNonQuery` 汇总受影响行数，`ExecuteReader` 返回最后一条命令的结果；取消与超时贯穿整批。不做服务端一次性批量语义。
- **SQL-15 复杂类型结构化取值**：连接字符串 `ComplexTypes=Structured` 时，`array<T>` 返回 `Object[]`、`map<K,V>` 返回字典、`row(...)` 返回 `Object[]`，元素按类型签名递归转换；默认（`String`）继续返回原始字符串以保持兼容。复杂类型作为写入参数仍按字符串字面量处理。

### 3.4 META — 元数据

- **META-1 GetSchema 集合**：实现 `GetSchema()` 与 `GetSchema(collectionName)`，至少提供 `MetaDataCollections`、`Tables`、`Columns`、`DataTypes`。
- **META-2 Tables 元数据**：查询 `information_schema.tables`，支持按 catalog/schema/table 过滤，返回表名、表类型、所属 catalog/schema。
- **META-3 Columns 元数据**：查询 `information_schema.columns`，返回列名、序号、数据类型、是否可空、默认值等。
- **META-4 DataTypes 元数据**：提供 Presto/Trino 常见类型与 .NET 类型映射的静态表，供 ADO.NET 工具与设计器使用。
- **META-5 服务端信息与版本**：通过 `/v1/info` 获取节点版本、环境、启动时间等信息；仅在 `TestConnection` 或显式 API 调用时请求。
- **META-6 Catalog/Schema 发现**：通过 `SHOW CATALOGS`、`SHOW SCHEMAS` 或 `information_schema` 查询发现可用 catalog/schema，结果做短期缓存。
- **META-7 能力探测**：根据服务端类型（PrestoDB/Trino）、版本与连接器，给出事务、写入、DDL 等能力的保守判断；驱动自身不声称支持未验证能力。
- **META-8 XCode 反向工程兼容**：XCode 通过 `information_schema` 获取表与列时，驱动需正确返回列类型、可空性与排序信息。
- **META-9 查询诊断 API**：提供只读的 `GetQueriesAsync`（查询列表）、`GetQueryInfoAsync(queryId)`（查询详情）与 `GetNodesAsync`（节点列表），用于诊断自己提交的查询；只复用公开 REST 接口，不实现 JMX、线程栈或任何修改/终止他人查询的管理操作。

### 3.5 COMPAT — 兼容性

- **COMPAT-1 PrestoDB 协议头**：默认使用 `X-Presto-*` 请求头，兼容 PrestoDB 0.2xx 及后续版本。
- **COMPAT-2 Trino 协议头**：`Protocol=Trino` 或 `TrinoHeaders=true` 时使用 `X-Trino-*` 请求头，兼容 Trino 351+ 的头重命名。
- **COMPAT-3 版本兼容**：对 PrestoDB/Trino 的响应字段做宽松解析，未知字段忽略、缺失字段使用默认值；不因新增状态或统计字段失败。
- **COMPAT-4 连接器差异**：写操作、事务、DDL 能力取决于底层连接器；驱动只保证协议层正确，服务端拒绝时原样抛出服务端错误。
- **COMPAT-5 网关/反向代理**：支持自定义 `Path` 前缀、代理 URL、额外请求头与自签名证书开关，适配 Trino Gateway、Nginx、负载均衡。
- **COMPAT-6 连接字符串别名**：兼容 XCode 习惯的 `Database`→`Catalog`、`Owner`→`Schema`、`Server`/`Data Source`→`Host`，以及 `UseSsl`/`EnableSSL`、`TrinoHeaders` 等写法。

### 3.6 I18N — 多语言

- **I18N-1 运行时词表**：`NewLife.Presto/Locales` 提供 33 种语言（含英文），键为英文源文，缺失译文回退英文。
- **I18N-2 编译期生成**：词表由 NewLife.Core 源生成器在编译期写入程序集，NativeAOT 与裁剪场景同样可用。
- **I18N-3 消息覆盖**：驱动产生的异常、日志与元数据必须进入词表；服务器返回的原文保持原样。
- **I18N-4 README 多语言**：`readme-languages.json` 维护 11 种语言，语言切换行由脚本生成，禁止手改。
- **I18N-5 校验与 CI**：键集合、占位符、未翻译项、英文源文、程序集元数据与 README 完整度均有脚本与 CI 门禁。
- **I18N-6 术语表**：维护跨语言术语与品牌白名单，保证 Presto/Trino/ADO.NET 等专有名词一致。

### 3.7 XCODE — XCode 集成

- **XCODE-1 DbProviderFactory 注册**：提供公开无参 `PrestoClientFactory`，可被 XCode `LoadFactory` 通过类型名与程序集名加载。
- **XCODE-2 工厂加载与回退**：XCode 优先加载 `NewLife.Presto`，未安装或加载失败时回退现有驱动；切换不改变已有部署行为。
- **XCODE-3 连接字符串映射**：接受 XCode 生成的 Host/Port/Catalog/Schema/User/Password/UseSsl/TrinoHeaders 组合，并兼容 Database/Owner 别名。
- **XCODE-4 参数化开关**：驱动支持 `@` 参数后，XCode 可将 Presto 的 `UseParameter` 从固定关闭改为按驱动能力开启。
- **XCODE-5 元数据/反向工程**：XCode 通过驱动查询 information_schema 时，表、列、类型与排序信息完整可用。
- **XCODE-6 能力边界与异常**：无事务、无自增、无 DDL/自动迁移、无批量能力；XCode 相关入口抛出明确 `NotSupportedException`，不产生半成功状态。
- **XCODE-7 真库冒烟**：XCode 对 Presto/Trino 的连接、查询、分页、元数据冒烟测试可在容器环境运行。

### 3.8 QA — 质量与交付

- **QA-1 离线单元测试**：连接字符串、参数替换、类型映射、错误解析、JSON 解析、状态机、重试策略均可在无服务端环境测试。
- **QA-2 假 HTTP 处理器测试**：用 `HttpMessageHandler` 模拟提交、轮询、503、错误、取消、压缩等响应，验证协议时序。
- **QA-3 真库集成测试**：可选连接真实 Presto/Trino（容器或外部服务），覆盖连接、查询、分页、元数据、取消；未配置时跳过。
- **QA-4 多平台 CI**：Windows x64、Linux x64、Linux arm64 原生 runner 构建全目标框架并跑单测；musl 容器与 macOS / Windows arm64 为观察期。
- **QA-5 包元数据与符号包**：NuGet 包包含 README、图标、许可证、符号包与 SourceLink；包元数据与仓库一致。
- **QA-6 NativeAOT 冒烟**：`net8.0+` 裁剪/AOT 分析零告警；AOT 发布冒烟覆盖 win-x64、linux-x64、linux-arm64，LoongArch64/musl/macOS 为观察期。
- **QA-7 多语言门禁**：词表一致性、翻译覆盖、英文源文、程序集/配置元数据、README 完整度与语言切换行全部纳入 CI。
- **QA-8 多指令集覆盖**：x64 与 arm64 原生验证，LoongArch64 与 riscv64 通过观察期构建覆盖，不阻断主干。

## 4. 🧊 暂缓清单

| 功能 | 暂缓理由 | 解冻前提 |
|------|----------|----------|
| EF Core / EF6 Provider | 必须独立成包并引入 EF Core 依赖，不能进入核心零依赖包；Presto 以分析查询为主，EF 的迁移/事务/写入模型匹配度低 | 有明确 EF 只读 ORM 需求，且只读查询场景验证通过 |
| OAuth2 交互式登录与刷新令牌轮换 | 需要浏览器/设备码或 IdP 交互，超出驱动核心职责；客户端凭据模式已支持 | 有企业 IdP 交互式接入需求，且能提供无交互令牌回调 |
| Spooling 协议 | 需要对象存储环境与 LZ4/zstd 解压解密实现，零第三方依赖约束下无法本地验证 | 有真实 spooling 集群与吞吐需求，并接受引入可选编解码包 |
| JMX / 线程栈 / 集群管理 UI | 属于集群运维接口，不是 ADO.NET 驱动核心；本轮只提供只读查询诊断 API | 有独立管理工具或运维需求，单独立项 |
| 服务端预编译语句 | REST 协议没有通用绑定参数；SQL `PREPARE/EXECUTE` 受连接器限制 | 服务端提供稳定、跨连接器可用的预编译协议 |
| riscv64 原生 CI | 缺少稳定 runner 与 SDK 组合 | 有可用 runner 或社区镜像 |

## 5. 不做什么

- **数据库服务端**：不实现 Presto/Trino 协调器、工作节点或连接器。
- **事务**：不实现 `BeginTransaction` 的提交/回滚语义；Presto/Trino 大多数连接器不支持事务。
- **DDL 与自动迁移**：不生成 CREATE/ALTER/DROP，不参与 XCode 自动建表；`Migration` 保持关闭。
- **自增主键**：Presto 无自增列；不模拟 `InsertAndGetIdentity`。
- **多语句**：一次提交只允许一条 SQL；不拼接多语句。
- **存储过程与游标**：Presto 没有传统存储过程/游标模型。
- **批量导入/COPY**：不实现类似 BulkCopy 的专用导入通道。
- **集群管理与查询历史 UI**：不做 Web 管理界面、查询历史浏览、JMX 与线程栈；只提供只读查询诊断 API（META-9）。
- **私有协议扩展**：只实现 Presto/Trino 公开客户端协议，不绑定某一发行版的私有扩展。
