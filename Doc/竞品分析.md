## 3. 关键差异说明

- **NewLife.Presto**：所有 ✅ 均有单测与真库（Trino 476 / PrestoDB 0.300）验证；事务、DDL、自增、存储过程明确不支持；EF 两个 Provider 只读，写入/迁移显式拒绝。性能上 `net6+` 直接解析 UTF-8 响应字节（`Utf8JsonReader` + 池化缓冲），旧目标保留 JsonParser 字典路径。
- **Spooling**：已实现 Trino 466+ 的 `X-Trino-Query-Data-Encoding` 协商、内嵌与对象存储分段、读取后确认；受零第三方依赖约束只声明未压缩 `json`，服务端没有该编码时自动回退直接协议。压缩编码（`json+lz4`/`json+zstd`）与真实对象存储集群验证仍缺。
- **NReco.PrestoAdo**：无连接级 GetSchema；用户名缺失会抛异常；`ExecuteNonQuery` 固定返回 1；参数用 `{name}`；默认 `CheckInterval=1000 ms`，单次查询被拖到 2.5–3.6 秒（参测时调到 50 ms）。
- **PrestoClient**：REST SDK，无 ADO 表面；已知问题：状态枚举解析、未启用压缩、批量拉取未合并、`varbinary` 按十六进制解析。
- **Trino.Ado / Trino.Client.ADO**：连 PrestoDB 需显式 `ServerType=Presto`；均无 `DbProviderFactory`，只能直接 new 连接；未声明 AOT 支持。取值也不标准：`GetValue` 对 `decimal` 返回自定义的 `TrinoBigDecimal`（不实现 `IConvertible`，`Convert.ToDecimal` 会抛 `InvalidCastException`），`GetDateTime` 对 `date` 列抛 `ArgumentException`，消费方必须按提供程序专有类型另写分支；本项目统一返回标准 `Decimal`/`DateTime`/`Int64`。
- **NH.Trino / Data.Presto / TriQL**：均为 Trino 单协议或来源不明的小包；NH.Trino 用 `Microsoft.Extensions.Logging` 且元数据只有作者 “Trino”，Data.Presto 无项目主页与描述，TriQL 只有 net10 目标。

## 5. 结论

- 同赛道开源 ADO 驱动仍是三个主力，新出现的小包只覆盖 Trino 单协议；高下载量的 Qsi/PreStorm 属于 SQL 构建器或 GIS 客户端，不构成替代。
- 能力覆盖：本项目在 ADO 表面、认证、元数据、类型、Spooling 与 ORM 上最全；ORM 是唯一同时覆盖 EF Core 6/8/10/11 与 EF6 的开源实现。
- 性能：建连、聚合、扫描、多列、宽表为 ADO 第一，标量与并发稳压两个官方系客户端（标量 7.5 vs 9.2–9.5 ms，并发 178.1 vs 162.7 次/秒）；托管分配只有竞品的 8%–30%（标量 11.1–15.7 KB、聚合 12.3–16.6 KB、扫描 0.54 MB、多列 0.94 MB、宽表 3.34 MB）。UTF-8 流式解析（v1.2）、同步通道（v1.3）、扁平行存储／字节直转（v1.4）、自解压＋跨页复用（v1.5）、默认不压缩（v1.6）、异步合并（v1.7）、认证头缓存与解析零碎分配（v1.8）、宽页扁平上限提升（v1.9）共同把差距拉到数量级。
- 取值兼容：官方系客户端的 `GetValue` 对 `decimal` 返回非 `IConvertible` 的自定义类型、`GetDateTime` 对 `date` 直接抛异常；本项目统一返回标准 ADO 类型，跨提供程序迁移无需改代码。
- 规模化：百万行扫描（TPC-H sf1 lineitem）本项目 557 ms / 71 MB / 峰值 55 MB，Trino.Ado 2466 ms / 164 MB / 145 MB，Trino.Client.ADO 2342 ms / 159 MB / 126 MB；三方校验和一致。TLS 仅首连多 3.3 KB 分配，握手被共享连接池摊薄。
- 剩余缺口：Spooling 压缩编码（LZ4/ZSTD）与真实对象存储集群验证；XCode 默认驱动切换属外部仓库改造。
- 差异化：零第三方依赖、`net45`~`net11`、NativeAOT、XCode 默认集成、三包同版本发布。
