## 3. 关键差异说明

- **能力面**：本项目在 ADO 表面、认证（Basic/JWT/OAuth2）、元数据、类型、Spooling、ORM 上覆盖最全；事务、DDL、自增、存储过程明确不支持，EF 两个 Provider 只读并显式拒绝写入与迁移。所有 ✅ 都有单测与真库（Trino 476 / PrestoDB 0.300）验证。
- **取值标准**：两个官方系客户端的 `GetValue` 对 `decimal` 返回非 `IConvertible` 的自定义类型（`Convert.ToDecimal` 直接抛异常）、`GetDateTime` 对 `date` 列抛异常；本项目统一返回标准 `Decimal`/`DateTime`/`Int64`，复杂列返回协议原始 JSON 文本。
- **协议细节**：Trino 系默认只发 `X-Trino-*`，连 PrestoDB 需显式切换服务器类型；本项目按 `Protocol=Presto` 切换。NReco 默认 `CheckInterval=1000 ms`，单次查询被拖到 2–4 秒。
- **剩余缺口**：Spooling 的 LZ4/ZSTD 压缩编码与真实对象存储集群验证（零依赖约束下只声明未压缩 `json`）。

## 4. 性能

同轮基准（同一进程、相同 SQL、串行执行，3 轮取中位；括号内依次为最快 ADO 竞品、原始 HTTP 基线）：

| 大方向 | Trino 476 | PrestoDB 0.300 |
|--------|-----------|----------------|
| 建连 + 首查 | **8.1 ms**（11.7 / 9.0） | **13.7 ms**（17.2 / 16.1） |
| 标量 `SELECT 1` | **7.5 ms**（9.2 / 7.4） | **13.2 ms**（17.7 / 13.0） |
| 聚合 15000 行 | **15.5 ms**（16.0 / 17.5） | **18.9 ms**（27.1 / 18.1） |
| 扫描 15000 行 | **20.8 ms**（76.5 / 20.3） | **32.6 ms**（52.6 / 35.8） |
| 多列类型 5000 行 | **21.1 ms**（22.2 / 22.9） | **38.2 ms**（40.2 / 49.5） |
| 宽表 16 列 5000 行 | **29.7 ms**（41.9 / 57.8） | **66.8 ms**（67.0 / 98.2） |
| 8 并发（次/秒） | 178（190 / 180） | 135（127 / 147） |

- **ADO 组内全部场景耗时第一**；托管分配只有竞品的 **8%–30%**，其中标量/聚合/并发三种情形还低于原始 HTTP 协议基线。并发吞吐与基线互有胜负（轮间波动 20%–80%）。
- 差距来自实现路线：UTF-8 流式解析与池化缓冲、扁平行存储、同步通道与对象复用、默认不压缩与终态免取消、复杂列原始文本、时间戳字节直转。完整数据与复现方式见 [性能测试](./性能测试.md)。

## 5. 结论

- 同赛道开源 ADO 驱动仍是 NReco.PrestoAdo、Trino.Ado、Trino.Client.ADO 三个；其余小包只覆盖 Trino 单协议，Qsi/PreStorm 属 SQL 构建器或 GIS 客户端，不构成替代。
- 能力覆盖最全：ADO 表面、认证、元数据、类型、Spooling、ORM，且 ORM 是唯一同时覆盖 EF Core 6/8/10/11 与 EF6 的开源实现。
- 性能全面占优：全部场景 ADO 第一，分配为竞品的 8%–30%（标量 11–16 KB、扫描 0.54 MB、宽表 3.3 MB），大结果集与宽表差距最大（扫描快 2–3.7 倍）。
- 取值兼容：统一返回标准 ADO 类型，复杂列返回协议原始 JSON 文本，跨提供程序迁移无需改代码。
- 规模化：百万行扫描 557 ms / 71 MB / 峰值 55 MB（官方系 2.3–2.5 s / 159–164 MB），TLS 仅首连多 3.3 KB 分配。
- 差异化：零第三方依赖、`net45`~`net11`、NativeAOT、XCode 默认集成、三包同版本发布。
