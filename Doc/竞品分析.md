## 1. 概述

### 1.1 分析目的

NewLife.Presto 的目标是成为 XCode 中 Presto 的默认 ADO.NET 驱动。本报告以用户指定的两个开源 .NET Presto 客户端为参考，回答三个问题：

1. 现有 .NET 生态已经覆盖了哪些能力，哪些是事实标准？
2. 它们的公开 Issue/PR 反映了哪些真实使用需求与兼容性风险？
3. 本项目首版应该做什么、暂缓什么、明确不做什么？

### 1.2 竞品筛选

| 代号 | 项目 | 入选理由 |
|------|------|----------|
| 参考实现 A | NReco.PrestoAdo | 面向 ADO.NET 的 Presto/Trino 适配器，与本项目定位最接近 |
| 参考实现 B | PrestoClient（BAMCIS） | Presto REST API 客户端，协议建模与重试/取消实现较完整，是 A 的底层依赖 |
| 参考实现 C | Trino.Ado / Trino.Core | 官方 Trino C# 客户端的持续维护分支，ADO.NET 实现最完整，是当前实际竞品 |
| 参考实现 D | Trino.Client.ADO | 官方客户端停止维护前的 ADO.NET 封装，存量项目仍在使用 |
| 参考实现 E | TrinoClient | 独立的 .NET Trino 客户端包，SDK 层 |

> 以上均为 MIT 许可的开源项目（`CData.Presto` 为商业授权，仅在 §1.4 生态全景中标注）。本报告的事实来自其 GitHub 仓库、NuGet 注册表、公开 Issue/PR 与本地实测，未做代码抄袭或逐行对比。

## 4. 值得借鉴之处

### 4.1 参考实现 A

- **薄适配层**：把 ADO.NET 表面与 REST 客户端分离，代码量小、职责清晰，便于替换底层客户端。
- **协议头切换**：用连接字符串 `TrinoHeaders` 在 Presto/Trino 之间切换，简单直接，用户无需改代码。
- **生产验证**：README 明确列出生产使用场景，说明该适配路径在实际业务中可行。
- **取消支持**：把 `CancellationToken` 贯穿到查询执行，并在读取器释放时清理底层请求。

### 4.2 参考实现 B

- **REST API 覆盖广**：除查询外还覆盖节点、线程、JMX、查询列表/详情，为运维工具提供了参考模型。
- **HTTP 重试**：指数退避 + 最大重试次数，处理瞬态错误。
- **模型层完整**：`QueryResults`、`StatementStats`、`QueryError` 等模型对协议字段建模细致，便于我们设计响应模型。
- **取消与异步**：全链路 `CancellationToken`，`Task.Delay` 替代 `Thread.Sleep`。
- **测试与 CI**：有测试工程与 CI 工作流，Issue/PR 讨论记录了真实兼容性问题。

## 6. 差距与机会

### 6.1 本项目的目标优势

- **XCode 默认集成**：工厂、连接串、参数化、元数据、能力边界按 XCode 需求设计，而不是通用客户端 + 薄适配。
- **零第三方依赖**：只依赖 NewLife.Core，减少 JSON/HTTP 包的传递依赖与版本冲突。
- **全框架覆盖**：`net45` ~ `net11`，与 XCode 一致；新框架满足 AOT/裁剪分析。
- **类型保真**：时间类型、decimal、二进制、UUID、IP 地址与复杂类型降级策略明确。
- **协议稳健**：状态字符串化、未知字段忽略、503/Retry-After、取消 DELETE、压缩默认开启。
- **可观测**：查询 ID、错误码、SQLState、耗时与 ActivitySource。

### 6.2 剩余差距与计划

v1.2 逐项核对后，真正未完成的能力只有下表六类；性能两项属于优化而非功能缺口。

| 能力 | 现状 | 计划 |
|------|------|------|
| `DbBatch` 批量命令（.NET 6+） | 已实现（顺序提交，行数汇总） | 完成（§9 DBBATCH-1） |
| OAuth2 认证 | 已实现客户端凭据模式 | 完成（§9 OAUTH-1）；交互式登录继续暂缓 |
| 查询诊断 REST API（查询列表/详情/节点） | 已实现只读诊断接口 | 完成（§9 ADMIN-1）；JMX/线程/管理 UI 仍不做 |
| 复杂类型结构化对象（array/map/row） | 已实现可选 `ComplexTypes=Structured` | 完成（§9 SQLC-1） |
| Spooling 协议 | 未实现 | 暂缓：需要对象存储环境与 LZ4/zstd 编解码，零依赖约束下暂不具备验证条件（§9 SPOOL-1） |
| EF Core / EF6 Provider | 已实现：`NewLife.Presto.EntityFrameworkCore`（EF Core 6/8/10/11）与 `NewLife.Presto.EntityFramework`（EF 6） | 完成（§9 EF-1）；只读查询，写入/事务/迁移不支持 |

### 6.4 性能实测摘要

完整数据、方法与局限见 [性能测试](./性能测试.md)。在单机 Trino 476 / PrestoDB 0.300 上、同进程串行测得：

| 指标（Trino 476） | NewLife.Presto | 参考实现 C | 参考实现 D | 参考实现 A（CheckInterval=50） | 原始 HTTP 基线 |
|-------------------|---------------:|-----------:|-----------:|----------------:|---------------:|
| 标量 `SELECT 1` 均值 | 35.8 ms | 30.3 ms | 29.8 ms | 261.0 ms | 17.0 ms |
| 聚合 15000 行 | 58.8 ms | 49.9 ms | 43.4 ms | 258.9 ms | 37.3 ms |
| 扫描 15000 行 | **76.4 ms** | 95.1 ms | 95.4 ms | 260.0 ms | 66.5 ms |
| 8 并发吞吐 | 46.8 次/秒 | **59.6 次/秒** | 45.3 次/秒 | 26.6 次/秒 | 53.4 次/秒 |
| 每次标量查询分配 | 156 KB | 97 KB | 95 KB | 90 KB | 16 KB |

结论：本项目在**大结果集扫描**上最快，在 **Trino 上的短查询延迟**优化后已与官方系客户端持平或更优（见 §4.4），**并发吞吐**处于第一梯队，**托管分配**仍偏高。参考实现 A 的默认 `CheckInterval=1000 ms` 会把单次查询拖到 2.5–3.6 秒。

## 8. 结论

- **市场格局**：.NET 生态里真正可用的 Presto/Trino **ADO.NET 驱动只有三个**（NReco、Trino.Ado、Trino.Client.ADO），其余高下载量包是 SDK、SQL 解析器或商业组件；本项目的空间在于“面向 ORM 的默认驱动”，而不是再做一个通用 REST 客户端。
- **本项目的差异化**：零第三方依赖、`net45`~`net11` 全框架、`@` 参数、连接级元数据、类型保真、协议稳健、可观测与 AOT，并由 XCode 直接消费。
- **能力对齐度**：参考实现 A/B 在本报告比较的 40 项能力上已全部被覆盖或明确不做；与官方系客户端相比，差距只剩 `DbBatch`、OAuth2、查询诊断 API、复杂类型结构化四项功能，本轮逐项补齐。
- **性能位置**：大结果集扫描最快、并发吞吐第一梯队；短查询延迟落后官方系客户端 5–20 ms（提前取消查询多一次往返），托管分配偏高 1.5–2.5 倍，这两项是下一阶段明确的优化目标。
- **对第三方项目的态度**：以上项目均以 MIT 许可公开（CData 为商业授权），提供了有价值的实现与真实 Issue/PR 反馈；本项目在设计中尊重并借鉴其公开经验，不贬低、不否定其适用场景。
- **成功标准更新**：Windows 与 Linux 双平台全量测试通过、覆盖率与 AOT 门禁通过、真库（Trino 476 / PrestoDB 0.300）集成通过、性能对比可一键复现。

## 9. 未完成功能点实施计划（v1.2）

> 逐项独立验收：功能 + 测试 + 文档三件齐备才算完成；未完成的保留在 [功能清单](./功能清单.md) 的暂缓项并写明前置条件。

### 9.1 DBBATCH-1 `DbBatch`（.NET 6+）

- **目标**：提供 `PrestoBatch`，支持 `DbBatchCommand` 列表按顺序提交；`ExecuteNonQuery` 返回各命令受影响行数之和，`ExecuteReader` 返回最后一条命令的结果；取消与超时沿用命令执行链路。
- **做法**：`#if NET6_0_OR_GREATER` 实现 `DbBatch`/`DbBatchCommand`，内部复用 `PrestoCommand`，不做多语句拼接。
- **验收**：假 HTTP 处理器验证顺序、行数汇总、取消；`PrestoClientFactory.CreateBatch` 可创建。
- **不做**：服务端一次性批量语义（REST 逐语句提交）。

### 9.2 OAUTH-1 OAuth2 客户端凭据

- **目标**：`Auth=OAuth2` + `TokenEndpoint`/`ClientId`/`ClientSecret`/`Scope`，用 `client_credentials` 获取 Bearer 令牌，按 `expires_in` 提前刷新；令牌不落日志。
- **做法**：新增令牌提供者，线程安全缓存；请求前按需获取；`AccessTokenProvider` 回调优先级最高。
- **验收**：假 HTTP 验证令牌请求体、缓存命中与过期刷新、401 时不重复无限刷新。
- **不做**：交互式登录、设备码、刷新令牌轮换（继续暂缓）。

### 9.3 ADMIN-1 查询诊断 REST API

- **目标**：只读接口 `GetQueriesAsync`、`GetQueryInfoAsync(queryId)`、`GetNodeInfoAsync`，返回查询状态、SQL、会话与错误信息；用于诊断自己提交的查询。
- **做法**：复用共享 `HttpClient` 与重试策略；服务端不支持时抛出带状态码的明确异常。
- **验收**：假 HTTP 处理器验证解析与重试；真库连 Trino 476 冒烟。
- **不做**：JMX、线程栈、杀掉他人查询、Web 管理界面。

### 9.4 SQLC-1 复杂类型结构化

- **目标**：连接字符串 `ComplexTypes=Structured` 时，`array<T>` 返回 `Object[]`、`map<K,V>` 返回 `IDictionary<String,Object?>`、`row(...)` 返回 `Object[]`，元素按类型签名逐层转换；默认仍返回原始字符串。
- **做法**：类型签名递归解析 + 复用 JSON 解析器；`GetFieldType` 对结构化复杂类型返回 `Object`。
- **验收**：嵌套 `array(map(varchar,row(...)))` 的解析测试；默认行为回归测试。
- **不做**：复杂类型作为写入参数（仍以字符串字面量传入）。

### 9.5 SPOOL-1 Spooling 协议（暂缓）

- **前置条件**：可用的对象存储后端 + LZ4/zstd 解压/解密实现。零第三方依赖约束下需自研解码器，且本地环境无法验证，暂不实现。
- **触发**：有真实 spooling 集群与吞吐需求时，先评估引入可选编解码包，再立项。

### 9.6 EF-1 EF Core / EF6 Provider（已完成）

- **交付**：两个独立包，核心包零依赖不变。
  - `NewLife.Presto.EntityFrameworkCore`：EF Core 6.0/8.0/10.0/11.0，`UsePresto(...)` 与 `AddPresto(...)`。
  - `NewLife.Presto.EntityFramework`：EF 6.5.2，`DbConfiguration.SetProviderServices` 注册。
- **能力**：LINQ 查询、`Count/Sum/Min/Max/Average`、`Where/OrderBy/Take/Skip`、`GroupBy`、导航属性连接、`EF.Functions.Like`、常用字符串/数学函数、`Database.Exists`。
- **边界**：`SaveChanges`、`Database.Create/Delete`、`Migrate`、`EnsureCreated` 建表一律抛 `NotSupportedException`；标识符大小写不敏感匹配，列名重映射（`HasColumnName`）在 EF6 下不生效。
- **验证**：真实 Trino 476 集成测试（查询/分页/聚合/连接/写入拒绝）+ 离线 SQL 生成与类型映射单测。

### 9.7 PERF-1 短查询往返

- **目标**：读取器提前关闭时的取消改为“尽力而为、不阻塞调用方”，消除标量/聚合场景多出的一次往返；显式 `Cancel()` 仍等待取消完成。
- **验收**：PerfTest 复测 `SELECT 1` 延迟与官方系客户端差距缩小；取消相关单测全部通过。

### 9.8 PERF-2 托管分配

- **目标**：削减每次查询的重复分配（请求头字典、CancellationTokenSource、字符串拼接）。
- **验收**：PerfTest 复测标量查询分配量明显下降；扫描场景不出现吞吐回退。
